# Синтетическая библиотека для #69

Python 3.10+, только стандартная библиотека. Генератор не читает пользовательские записи, создаёт тихие WAV и вымышленные JSON/Markdown. Каталог назначения и соседний manifest не должны существовать.

```sh
python3 docs/ux/redesign-2026-10/fixtures/create-fixtures.py /tmp/verbemo-ux69-new/recordings
```

Создаются 4 встречи: 18 реплик / 3 говорящих, 180 реплик / 9 говорящих, ошибка, отложенная обработка. У первой встречи есть предыдущая версия из 6 реплик. Имена вымышленные, email использует `example.invalid`; длительности WAV проверяются assertions. `fixture-manifest.json` рядом с каталогом позволяет сравнить байты до/после UI-действий.

Первый набор не покрывает специального неизвестного `?`, ошибочную ранее сохранённую связь, пустую библиотеку и реально выполняющееся задание. Они дополнены отдельным набором 30.10, см. ниже. «Отложено» при выключенной обработке не означает наличие работающей очереди.

## Изоляция запуска

Не направлять рабочее установленное приложение на эти данные и не копировать в профиль настоящие credentials. Перед запуском проверить эффективный профиль и выключить transcription, live_transcription, summary, speaker_names, auto_record, calendar, MCP. Настройки ОС/разрешения не требуются для просмотра готовых материалов.

На Mac в текущем проходе использован отдельный bundle `name.ekho.verbemo.ux69` с закреплённым через `LSEnvironment` значением `CFFIXED_USER_HOME` на `.build/ux69/home`, явным `recordings_dir` и завершённым setup-маркером. `HOME` не переназначался. Версия UI 0.17.2; вспомогательные ресурсы взяты из установленного scaffold, поэтому это не release acceptance. `start_at_login` не является поддерживаемым ключом Mac config и не добавляется.

В Windows `VERBEMO_TEST_DATA` работает только в Debug и задаётся на отдельный существующий корень теста. Там лежит `config.json` с явным `recordings_dir`; DEBUG-реализация также разделяет credential prefix и IPC identity. Для другой машины пересоздать конфигурацию с её путями, а не использовать подготовленный здесь абсолютный путь к SDK.

Подготовленная на Parallels копия: `%TEMP%\VerbemoUX69-20261029\app`; запуск — `launch-ux69.cmd` в том же корне. Исходный build log: `C:\Windows\Temp\VerbemoUX69-20261029\build.log`. Это только подготовка; запуск текущей сборки и GUI-проверка не подтверждены. 30.10 пользователь поручил пропустить Windows в текущем проходе.

## Сценарии следующего прохода

1. Открыть «Планирование», сводку/расшифровку/участников. Найти авторов реплик 2, 3, 6. Зафиксировать размер и время выполнения человеком.
2. Назначить говорящего 3 Вере; проверить все 6 реплик, повторное открытие/перезапуск, неизменность исходного JSON/audio и архива. Затем отдельно проверить исправление ошибочной связи, отмену и снятие связи.
3. Поиск «Атлас» → две встречи; «Кварцевый компас» → ожидается поиск по расшифровке; «Сапфировый маяк» → по сводке; случайный запрос → честное отсутствие совпадений. Проверить отдельно поиск внутри встречи и переходы к результатам. Записать фактическое, даже если функция отсутствует.
4. Найти язык интерфейса, язык встреч, место хранения, выбор локальной/облачной обработки. Не запускать облачную обработку, не вводить ключи и не загружать модели.
5. Длинная встреча: дойти до 29:50, проверить подписи и прокрутку. Открыть архив короткой встречи; не путать имена разных версий. Сравнить error/deferred, затем отдельно подготовить контролируемое выполняющееся задание.
6. Повторить нужные состояния RU/EN, light/dark, обычный/минимальный размер, мышь/клавиатура. Сохранять снимки только тестового окна. Сборку/CI не засчитывать за GUI.

```sh
python3 docs/ux/redesign-2026-10/fixtures/create-followup-fixtures.py /tmp/verbemo-ux69-followup-new/recordings
```

### Контролируемая сводка без модели

Только в QA config оставить `summary.enabled=false`, установить `summary.backend=ollama`, `summary.ollama_model=ux69-synthetic`, `summary.ollama_base_url=http://127.0.0.1:18969`. Остальные обработчики и интеграции остаются выключенными. Создать рядом с набором `summary-mode.txt` с единственным словом `hold` и запустить:

```sh
python3 docs/ux/redesign-2026-10/fixtures/mock-summary.py /tmp/verbemo-ux69-followup-new/summary-mode.txt
```

В UI выбрать «Планирование» → повтор сводки → Ollama; проверить адрес назначения → «Проверить и создать». `hold` держит ответ до 180 секунд. Дождаться настоящего POST и видимого активного задания, отменить через UI, проверить Queue: 0 и неизменность SHA256 старой сводки. Затем изменить содержимое mode-файла на `error`, повторить и проверить ошибку/старую сводку. Изменить на `success`, повторить и проверить новый текст. Закончить сервер Ctrl+C. Это тест жизненного цикла интерфейса, а не Ollama/inference acceptance.

Минимальная самопроверка сервера при `success` (только localhost):

```python
import json, urllib.request, urllib.error
base = 'http://127.0.0.1:18969'
assert json.load(urllib.request.urlopen(base + '/api/tags', timeout=3))['models'][0]['name'] == 'ux69-synthetic'
request = urllib.request.Request(base + '/api/chat', data=b'{"model":"ux69-synthetic"}')
assert 'UX69' in json.load(urllib.request.urlopen(request, timeout=3))['message']['content']
try:
    urllib.request.urlopen(urllib.request.Request(base + '/api/chat', data=b'{}'), timeout=3)
    raise AssertionError('invalid request accepted')
except urllib.error.HTTPError as error:
    assert error.code == 400
```

Результаты живых действий, сохранности и ограничения находятся в отчёте и `evidence/verification-20261030.json`. WAV содержит тишину: движение плеера не подтверждает слышимость голоса. Восстановление проверено немедленным Undo в 6.5-секундном окне; перенос после задержки и Finder Trash recovery не проверялись.
