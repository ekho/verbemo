## Один сценарий, сначала Mac

Открыть учебную встречу → прочитать несколько реплик и различить говорящих → прослушать фрагмент → исправить участника карандашом рядом с именем → найти фразу в расшифровке и сводке → очистить поиск и продолжить чтение с прежнего места. Повторить в архивной версии и на длинной встрече. После приёмки Mac выполнить тот же сценарий на Windows.

| Входит в пилот | Граница |
|---|---|
| Список/встреча и локальный стиль Studio | Сохранить текущие запись, импорт, настройки, меню и нижнюю строку; затронуть только необходимые точки входа и стили поверхности встречи |
| Шапка, версии, вкладки, детали | Те же сервисные данные и права действий; скрытие/возврат списка и узкое окно |
| Компактные реплики | Колонка говорящего, буква/имя, карандаш, время, выделение/копирование текста; сохранение позиции при обновлениях |
| Назначение | Существующий календарный выбор и ручное имя; подтверждение области, сохранение/ошибка/отмена; запись только в выбранную версию |
| Плеер | Настоящие существующие аудиодорожки, seek, Play/Pause/Stop; сохранить скорость, громкость, смещения источников |
| Поиск внутри встречи | Реальная подстрока в выбранной версии расшифровки/сводки, подсветка, навигация и восстановление контекста |

В #73 остаются полнотекстовый индекс библиотеки, поиск/перекомпоновка настроек, полный перенос экрана записи и других сценариев из карты функций. В пилоте фильтр библиотеки подписан по фактической возможности: «Название встречи». Не менять форматы данных, ASR/диаризацию, обработку/отмену, сетевые API, релизный маршрут или бренд. Не добавлять экспериментальный web UI внутрь приложения.

## Где использовать SwiftUI

**Рекомендую гибрид: новая шапка встречи на SwiftUI внутри AppKit.** В неё входят версии, вкладки, локальный поиск и кнопка деталей. Польза — одна декларация состояний и адаптивной компоновки вместо нескольких ручных наборов constraints. Это инженерная гипотеза: пилот должен подтвердить фокус, resize и отсутствие лишних обновлений.

| Поверхность | Решение пилота | Почему |
|---|---|---|
| Шапка и поиск Mac | Новый `StudioMeetingHeader` через `NSHostingView`; одна модель состояния в `MeetingLibraryController` | Ограниченное применение SwiftUI, проверяемая польза для состояний и переноса элементов |
| Расшифровка Mac | Изменить существующий `MeetingTranscriptView` / `NSTableView`, сохранить selectable native text | Сейчас таблица повторно использует строки и рассчитывает их высоту. Полный перенос длинного текста не нужен для проверки новой композиции |
| Назначение Mac | Существующий `SpeakerAssignmentEditor` в компактном popover с подтверждением, открываемом карандашом | Сохранить правила ручного имени/календарного ID и cleanup accessibility у dropdown; отдельная модель записи не нужна |
| Аудио Mac | Существующий `MeetingPlaybackView` и AVPlayer | Один источник состояния воспроизведения; замена визуальных контролов не пересоздаёт player |
| Windows | Существующий C#/WPF, `SpeakerIdentityEditor`, `MeetingPlayer`; адаптация строк и поиска | Эквивалентный сценарий без смены UI-стека; настоящий текст должен выделяться и копироваться |

Контроллер владеет выбранной встречей/версией, поисковым контекстом и загрузками. SwiftUI получает состояние и отправляет действия; не читает файлы и не создаёт второй player. При смене версии результат async-загрузки проверяет ключ встречи + версии + поколение запроса. Sheet/popover после смены встречи закрывается, сохранение повторно проверяет актуальность и возможность записи.

Если фокус/высота шапки или lifecycle моста мешают приёмке, сначала исправить узкую границу; откат только шапки на AppKit допустим с записанным результатом проверки. Это не повод отказаться от SwiftUI во всём приложении. Другие экраны оценивать по итогам пилота.

## Что уже есть в коде

Проверено по исходникам ветки на `caf46e5` (30.10.2026), а не по браузерному макету:

- Mac: `MeetingLibraryController.showDetail` читает выбранный artifact directory, связывает `meetingTranscript.onPlayFrom` с `audioPlayer.play(from:)`, пишет назначение через `PostProcessor.setSpeakerParticipant(_:participant:name:in:)`. Ограничения `canEdit` учитывают занятость/claim/request/final diarization. Сейчас обновление details возвращает текст в начало — это нужно исправить для согласованного сохранения позиции.
- `MeetingTranscriptView` — `NSScrollView` с переиспользуемыми `NSTableView`-строками, выделяемым текстом и измерением высоты. `MeetingPlaybackView` сохраняет player при тех же sources; скорость включает 0.75/1/1.25/1.5/2 и есть громкость. Эти возможности не сокращаются до набора HTML-макета.
- Windows: `RecordingsWindow.ShowTranscriptAsync` использует `transcriptShown` для защиты от устаревших загрузок и `TranscriptVersion.Directory` для версий. `SpeakerEditor` вызывает `SetSpeakerParticipantAsync` / `SetSpeakerNameAsync`. JSON-реплики сейчас создаются как StackPanel-строки через `ShowTranscriptParticipantsAsync`; не считать их автоматически виртуализированными или выделяемыми. `MarkdownPreview` — отдельный RichTextBox для markdown.
- Фильтры библиотеки вызывают `MeetingPresentation.matches` / `Matches`; поиск по содержимому в макете не доказывает наличие полнотекстового индекса в приложении.

Новые API поиска и состояния в инженерном плане — предложения, не существующие функции. Данные назначений/версий и аудио остаются под текущими сервисными контрактами.

## Приёмка пилота

| ID | Проверка на каждой ОС | Критерий |
|---|---|---|
| P01 | Короткая и длинная встреча, архив; список скрыть/вернуть, детали, настройки/назад | Выбранная встреча/версия не меняется самопроизвольно, позиция сохраняется; цвет не единственный способ различать голоса |
| P02 | Выделение/копирование RU/EN/emoji, rapid scroll и resize на длинной записи | Текст копируется без пропусков/искажения; нет падений, наложений или потери доступности действий |
| P03 | Карандаш C → Вера; ручное имя; отмена; повтор при ошибке; busy/unknown | Все реплики этого голоса в выбранной версии обновлены, другие версии неизменны; ввод сохранён при ошибке, фокус возвращён |
| P04 | Play → Pause → продолжить → время реплики → Stop → конец → повтор | Реальный player правильно меняет позицию/состояние; скорость/громкость сохранены, нет второго audio lifecycle |
| P05 | «Кварцевый компас» / «Сапфировый маяк», другой регистр, emoji, повторы, пусто/нет результатов | Найдены реальные тексты выбранной версии; подсветка и число согласованы, Enter/Shift+Enter работают, очистка возвращает исходное место |
| P06 | Поиск + быстро сменить версию/встречу; открытый редактор + сменить встречу; ошибка чтения | Старый ответ не попадает в новую встречу; позднее сохранение не меняет другой artifact; отсутствие результата отличается от ошибки |
| P07 | Светлая/тёмная, RU/EN, минимальное окно, 150/200% текста, Windows DPI отдельно | Все действия доступны, имя/текст не обрезаны, горизонтальная прокрутка для обычного текста не требуется; остаётся область чтения |
| P08 | Keyboard-only, VoiceOver/Narrator, повышенный контраст, Reduce Motion | Понятные имена/состояния, видимый фокус и возврат из popover/details; нет ловушки на стыке SwiftUI/AppKit |
| P09 | Занятая обработкой встреча + навигация; сохранность файлов | UI не создаёт повторных операций. Чтение/поиск не пишет данные; назначение меняет только допустимые производные артефакты выбранной версии |

Набор данных: заново сгенерировать [изолированные fixtures](fixtures/README.md) в новом временном каталоге; не использовать личную библиотеку/настройки. Перед прогоном записать SHA файлов. После чтения/поиска хеши идентичны. После назначения отдельно перечислить ожидаемые изменения (`speakers.json` и пересозданные сервисом текстовые артефакты), проверить аудио, метаданные и другие версии побайтно. Не предполагать, что назначение меняет только один файл.

Существующее fixture-аудио — тишина: оно годится для seek/clock, не доказывает слышимый звук. Для P04 добавить короткий синтетический тон через существующие test-audio helpers и проверить воспроизведение вручную. Не запрашивать микрофон и не запускать платные/реальные модели ради этой проверки. Processing/busy проверять изолированными фикстурами, чётко отмечая моделируемые состояния.

Для каждой ОС сохранить commit, ОС/SDK, параметры сборки и профиля, фактические команды/результаты, шаги P01–P09, снимки и ограничения в `evidence-72/`. Выполнение тестов и GUI — отдельные свидетельства. Числовое ускорение работы не заявлять без человеческого baseline; собрать замечания пользователя к реальному Mac-пилоту перед Windows.
