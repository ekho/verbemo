## A. Библиотека рядом с рабочей областью — моя рекомендация

Список встреч остаётся слева, справа — выбранная встреча. Расшифровка, сводка и участники переключаются внутри встречи. Контекст и обработка открываются по явной кнопке «Детали», не занимая постоянную третью колонку. «Скрыть список» освобождает ширину для чтения; возврат к списку остаётся видимым.

```text
┌───────────────────────────────────────────────────────────────┐
│ Встречи   Новая запись   Импорт                    Настройки   │
├───────────────────┬───────────────────────────────────────────┤
│ По всей библиотеке│ Планирование            Детали   Действия │
│ Все / Обработка / │ Версия: текущая       Найти в этой встрече│
│ Требуют внимания  │ Расшифровка | Сводка | Участники           │
│                   │ ▶ 00:20 / 03:00 ──────────── скорость     │
│ > Планирование    │                                           │
│   Длинная встреча │ A · Анна       00:10       Изменить имя   │
│   Атлас…          │ Текст реплики…                            │
│                   │ C · Борис      00:20       Изменить имя   │
│ Скрыть список     │ Кварцевый компас…                         │
├───────────────────┴───────────────────────────────────────────┤
│ Состояние записи / пауза / завершить · Очередь / предупреждения│
└───────────────────────────────────────────────────────────────┘
```

**Путь:** результат поиска в левом списке → нужная вкладка и фрагмент справа → «Изменить имя» у говорящего → результат на месте. Другая встреча открывается из того же списка. Настройки заменяют рабочую область целиком, со своей навигацией; возвращение восстанавливает встречу, версию, вкладку и место чтения.

**Плюс:** быстро переключаться между найденными встречами, сохраняя видимую выдачу. **Компромисс:** список отнимает ширину; нужно заметное управление его видимостью. В узком окне список становится отдельным представлением с возвратом, а не сжимает текст до узкой колонки. A отличается от нынешнего Journal прежде всего плотностью шапки, контекстными деталями и явными действиями у говорящего, а не самой идеей списка слева.

## B. Библиотека → отдельный экран чтения

Библиотека использует всю рабочую область: поиск, фильтры, строки встреч и фрагменты совпадений. Открытие встречи заменяет её экраном чтения; списка рядом нет даже в широком окне. Возврат сохраняет запрос, фильтр, выделение и прокрутку библиотеки.

```text
Библиотека                         Открытая встреча
┌─────────────────────────┐       ┌────────────────────────────┐
│ Новая запись  Импорт     │       │ ← Результаты поиска        │
│ По всей библиотеке      │       │ Планирование   Детали  ⋯   │
│ Все / Обработка / …     │       │ Версия   Найти во встрече  │
│                         │       │ Расшифр. | Сводка | Люди   │
│ Планирование            │  →    │ ▶ 00:20 / 03:00 ─────────  │
│ «…Кварцевый компас…»    │       │ A · Анна    Изменить имя   │
│ источник: расшифровка   │       │ Текст реплики…             │
│                         │       │ C · Борис   Изменить имя   │
│ Длинная встреча         │       │ Кварцевый компас…          │
├─────────────────────────┤       ├────────────────────────────┤
│ Запись / Очередь        │       │ Запись / Очередь           │
└─────────────────────────┘       └────────────────────────────┘
```

«Люди» в схеме сокращено только ради ширины; название раздела во всех вариантах — «Участники».

**Путь:** найти встречу/фрагмент в библиотеке → открыть читатель → изменить имя на месте → вернуться к сохранённой выдаче для другой встречи. Настройки открываются как самостоятельная страница того же окна, с возвратом к исходному экрану. Запись и очередь доступны при любом переходе.

**Плюс:** максимум места для одного текста, одна навигационная логика в узком и широком окне. **Компромисс:** сравнение нескольких встреч требует возвратов; длинный список результатов нельзя видеть одновременно с расшифровкой. Это сильный вариант, если основная работа — долго читать одну встречу.

## C. Встреча как единый документ

После библиотеки открывается один документ с оглавлением «Сводка / Участники / Расшифровка / Контекст». Все разделы находятся в одном потоке, переключения вкладок нет. Оглавление перемещает к разделу; результат поиска сразу открывает нужный фрагмент, не заставляя прокручивать сводку. Сводку и список участников можно свернуть.

```text
┌───────────────────────────────────────────────────────────────┐
│ ← Библиотека  Планирование   Версия   Найти во встрече    ⋯    │
├────────────────┬──────────────────────────────────────────────┤
│ Оглавление     │ ▶ 00:20 / 03:00 ─────────────────── скорость │
│ Сводка         │ СВОДКА                         Свернуть     │
│ Участники      │ Решения встречи…                            │
│ Расшифровка    │ УЧАСТНИКИ                      Свернуть     │
│ Контекст       │ A · Анна    C · Борис — Изменить имя         │
│                │ РАСШИФРОВКА                                 │
│                │ A · Анна     00:10    Изменить имя           │
│                │ Текст реплики…                              │
│                │ C · Борис    00:20    Изменить имя           │
│                │ Кварцевый компас…                           │
├────────────────┴──────────────────────────────────────────────┤
│ Состояние записи / пауза / завершить · Очередь / предупреждения│
└───────────────────────────────────────────────────────────────┘
```

**Путь:** библиотека → документ → раздел по оглавлению или результату поиска → назначение на месте. Календарь и параметры результата — раздел «Контекст», текущая обработка — рядом с соответствующим результатом. Настройки — отдельная страница с возвратом к якорю документа. В узком окне оглавление сворачивается в явно подписанный выбор раздела.

**Плюс:** вся встреча воспринимается одним документом; сводка, люди и исходный текст доступны в одном потоке. **Компромисс:** очень длинные встречи требуют надёжного оглавления и сохранения позиции; появление сводки или раскрытие разделов не должно сдвигать читаемую реплику. Сложнее показать, какой результат относится к выбранной версии. Для поставленного приоритета длинного чтения я предпочитаю A или B.

## Общие решения, предлагаемые во всех трёх вариантах

### Реплики и назначение

Имя и устойчивое обозначение говорящего видны у каждой группы реплик; отступ и типографическая иерархия различают группы без зависимости от цвета. Чередование говорящих не превращаем в двухсторонний чат: их может быть девять. Время остаётся переходом к общему аудио; «Изменить имя» — отдельное подписанное действие, доступное клавиатурой.

В редакторе показываем текущую связь, выбор приглашённого, ручное имя и «Снять связь». Перед подтверждением: «Все реплики говорящего C в выбранной версии». Это не изменение отдельной фразы и не редактирование события календаря. Сохранение обновляет все затронутые реплики; Escape закрывает без изменений и возвращает фокус к вызвавшей кнопке. Если встреча/версия успела смениться, редактор закрывается без применения к новой области.

Для специального `?` не предлагаем массовое назначение: нет надёжно определённого говорящего. Вместо ложного приглашения нажать — объяснение недоступности. Назначение отдельной неизвестной фразы потребовало бы другой модели данных и не входит в этот этап.

### Поиск и результат

Два явных входа: «По всей библиотеке» и «Найти в этой встрече». В выдаче видны название, источник совпадения («Расшифровка»/«Сводка»), фрагмент и версия, если применимо. Переход ведёт к совпадению с окружающим текстом. «Нет совпадений» отличается от «В библиотеке пока нет встреч»; выход из поиска возвращает прежнее выделение и позицию.

**Разрыв возможностей U01:** поиск по содержимому и переход к фрагменту отсутствуют в проверенной исходной версии. В #70 это только предложенное поведение и будущая имитация на синтетических данных. Разработка индекса/механизма поиска требует отдельной оценки в инженерном плане; макет не подтверждает его готовность. Для первого макета предлагаю искать по текущим результатам всей библиотеки, а внутри встречи — по выбранной версии и доступной сводке. Поиск по всем архивам библиотеки — открытый вопрос объёма, не молчаливое обещание.

### Настройки

Отдельная страница в том же окне. Вместо списка встреч слева — категории настроек, сверху явное возвращение к прежней встрече. В узком окне сначала список категорий, затем выбранная категория с возвратом. Названия ниже — предложения; конкретные поля и текущие значения сохраняются.

| Категория | Что пользователь здесь меняет | Задание из проверки |
|---|---|---|
| Приложение | Язык интерфейса, тема, запуск, общие параметры | Переключить интерфейс на английский |
| Запись и доступ | Источники, автоматическая запись, системные разрешения | Понять, почему запись недоступна |
| Расшифровка | Язык речи, локальная/облачная обработка, модель, разделение говорящих, live-текст | Выбрать язык встречи; понять место обработки |
| Сводки | Способ и параметры генерации, автоматический запуск | Отличить настройку будущих запусков от повторной сводки текущей встречи |
| Хранилище и модели | Путь записей, сохранение аудио, загрузка и удаление моделей | Найти место хранения |
| Календарь — только Mac | Действующие настройки календарей и собственных адресов | Выбрать используемые календари |
| Подключения → MCP | Действующие параметры локального MCP и подключения | Найти инструкцию подключения; секреты замаскированы |
| О приложении | Версия, ссылки и проверка обновлений | Узнать установленную версию |

Это группировка существующих настроек, не новые интеграции. Параметры выбранной версии и повторной обработки доступны из самой встречи с подписанной областью действия; глобальные настройки явно относятся к следующим операциям. Поиск по настройкам не добавлен: он не входил в согласованный охват поиска.

## Переходы и сохранение контекста — предлагаемые правила

Эта таблица — контракт макета; фактически пройденные сценарии и границы вынесены в [отчёт](prototype-a-review.md). Данные состояния: выбранная встреча и версия, вкладка/раздел, позиция текста, запрос и фильтр библиотеки, активная запись и конкретное задание обработки. Последние два не меняются из-за перехода на другой экран.

| Переход | Что должно произойти | Выбор и фокус |
|---|---|---|
| Начать запись → читать старую встречу → настройки | Полоса показывает активную запись, время и доступные паузу/завершение; возврат открывает её live-экран | Новая выбранная встреча не становится записываемой; фокус идёт в открываемый экран |
| Завершить запись → ожидание → обработка | В библиотеке появляется соответствующее состояние; текст не подменяется ложным готовым результатом | Окончание фонового задания не переключает текущую встречу и не крадёт фокус |
| Другая встреча | Закрыть несохранённый редактор участника без применения к другой встрече; привязать плеер к новой встрече, остановив прежнее воспроизведение | При возврате восстановить выбранную версию и якорь; по первому открытию — начало нужного раздела |
| Другая версия | Явно поменять подпись версии и связанные реплики/имена; закрыть редактор до применения | Сохранить позицию отдельно для каждой версии; не переносить старый индекс реплики на другой текст |
| Найти → открыть совпадение → вернуться | Показать источник и фрагмент с контекстом; не менять библиотечный запрос автоматически | A сохраняет выдачу рядом; B/C — при возврате; выход из локального поиска возвращает место чтения |
| Начать повторную обработку | Показать новое задание и область действия; прежний готовый результат остаётся читаемым | Текущий архив не заменяется новым автоматически; переход к новому результату — явное действие |
| Отменить → очистка → остановлено | Только поддерживаемая отмена; кнопка не объявляет успех до завершения очистки; готовые результаты сохранены | Встреча/версия и место чтения сохраняются |
| Ошибка → подробности → повтор | Причина и доступное действие видны рядом с результатом; повтор привязан к тому же заданию/встрече | Не отправлять человека искать причину в другой части приложения; фокус возвращается к доступному действию |
| Удалить → отменить подтверждение / Undo | Подтверждение сохраняет встречу при Cancel; после удаления доступно ограниченное по времени восстановление | Cancel возвращает фокус к команде; Undo возвращает строку, не похищая текущий выбор. Восстановление из системной корзины вне проверенного пути |
| Настройки → назад | Вернуться к исходному экрану и данным, сохранив запись/очередь | Восстановить встречу/версию/раздел/якорь и кнопку, открывшую настройки |
| Закрыть окно / выйти | Сохранить существующие различия закрытия окна, фоновой работы и выхода; не вводить скрытой отмены записи | Реальная проверка lifecycle — нативный этап; браузерный макет её не доказывает |

## Нативная адаптация и проверка после выбора

Apple допускает явное управление скрытием боковой панели через кнопку и меню View; Microsoft описывает адаптивный список с деталями, где узкий размер требует продуманного возврата. Это поддерживает применимость A, но не доказывает, что A удобнее B для Verbemo. [Apple Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars), [Microsoft List/details](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/list-details), проверены 30.10.2026.

Предложение по командам: ⌘F / Ctrl+F ищет внутри открытой встречи, а в библиотеке — по библиотеке; отдельная видимая команда «По всей библиотеке» доступна всегда. Это изменение нынешней привязки ⌘F к библиотеке и требует проверки в макете, а затем в нативном пилоте, включая русскую раскладку. Глобальные сочетания не назначены наугад. ⌘, / Ctrl+, сохраняют вход в настройки. Tab/Shift+Tab проходят по действиям, Escape закрывает редактор/поиск с возвратом фокуса; действие доступно без hover и без распознавания цвета.

Размеры проверки будущего макета: Mac 1340×848 и минимум содержимого 760×600; Windows 1280×800 и заданный в коде минимум 820×520. Размеры браузерного макета — CSS-пиксели, размеры native-пилота — единицы соответствующей ОС; не выдавать один за другой. Не поднимать минимальные требования ради макета. Свёрнутая панель имеет заметную кнопку возврата; шапка не должна вытеснять всю расшифровку. RU/EN и длинные названия должны помещаться или переноситься без исчезновения действий.

В будущем макете запись, обработка, назначения и поиск явно помечаются как демонстрация на вымышленных данных; результат сохраняется рядом с этим файлом и работает без обязательного временного сервера. До нативного пилота макет не доказывает AppKit/SwiftUI, WPF, VoiceOver/UI Automation, масштабирование ОС, реальную запись или поиск пользовательских файлов.
