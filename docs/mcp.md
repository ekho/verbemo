# Local MCP access

Verbemo's local MCP service lets a local AI client find saved meetings, read transcripts and summaries, and obtain saved audio. Enable it in the dedicated MCP settings page. The application must remain running; closing its window keeps the service available, and quitting or disabling MCP closes access.

This guide accompanies issue #63. Runtime acceptance and exact client versions are recorded in the [testing report](testing/2026-10-28-local-mcp.md); a configuration example alone does not establish compatibility.

## Windows status

**MCP on Windows may be unstable.** Windows builds and focused native tests have
passed, but whole-app GUI and real model-client acceptance remain unverified.
A known audio timeout gap can leave an HTTP request waiting if file opening or
reading stalls. Repeated immediately completed bridge requests can also retain
bookkeeping entries and gradually increase memory use. Further Windows work
was stopped at the user's request; these issues are not reported as fixed.

## Connect a client

Open Settings → MCP and enable the service. When it is off, only the MCP toggle is shown. When enabled, Server, Connection and Access expand within the same card. Choose a client under Connection: the MCP URL, console command and complete local-agent setup prompt each have their own Copy button, with manual steps below. The instructions use this copy of the executable and the selected valid port. Server distinguishes the selected endpoint from the endpoint actually listening; an enabled toggle alone does not establish a working connection. Invalid port input or an unreadable configuration disables dependent copy actions.

The HTTP endpoint is `http://127.0.0.1:<port>/mcp`. The default port is 52763; valid custom ports are 1024–65535. Changing the port updates the displayed and copied HTTP examples. A port conflict is reported rather than silently selecting a different port.

For full audio acquisition, use the native stdio bridge in the Verbemo executable:

```text
<verbemo executable> mcp --output-dir <client-owned directory>
```

The output directory is optional. Without it, the bridge creates a private temporary directory. It reads the application's local port and credential settings; there is no separate `--port` argument. It does not start the application or read the meeting library itself. Python and Node.js are not required by the bridge.

Run the client on the same computer and under an account that can read Verbemo's local credentials. The next operation performed by the client must be able to open the downloaded files. A remote backend or cloud-only chat cannot reach this localhost endpoint automatically.

### ChatGPT / Codex in a local environment

Use the Codex command generated by the application. Its registration form is `codex mcp add verbemo -- <executable> mcp`. Add the output directory when the client's workspace or sandbox needs a particular artifact location. Restart or refresh the client's MCP connection after changing its registration.

This route applies to a local Codex runtime. It does not configure a cloud ChatGPT connector.

### Claude Desktop

Merge the generated `verbemo` entry into the local MCP configuration, preserving other entries. The fragment uses `mcpServers`, an executable `command`, and an `args` array beginning with `mcp`.

The manual configuration is available through Developer → Edit Config in the older settings layout; newer layouts group local MCP servers under Desktop app → Extensions. Restart Claude Desktop after changing its configuration. The local configuration file is `~/Library/Application Support/Claude/claude_desktop_config.json` on macOS or `%APPDATA%\Claude\claude_desktop_config.json` on Windows. See the [official local-server guide](https://modelcontextprotocol.io/docs/develop/connect-local-servers).

A connection and tool listing do not by themselves prove that the client's next operation can use an audio file. Check the testing report for the verified mode and required local file access.

### Claude Code

Use the generated `claude mcp add --transport stdio verbemo -- <executable> mcp` command in the project that should use it. Claude Code's default registration scope is local to that project. Its [MCP documentation](https://code.claude.com/docs/en/mcp) describes other scopes.

The installed Claude Code client was not logged in during initial testing. Its runtime compatibility remains unverified unless the testing report records a later successful run.

### OpenCode

Use the generated `opencode mcp add verbemo -- <executable> mcp` command from the intended project. In OpenCode v2, the manual configuration belongs under `mcp.servers.verbemo`, with `type: "local"` and an executable/argument array in `command`. The v1 configuration shape is different. See [OpenCode v2 MCP configuration](https://dev.opencode.ai/v2/docs/mcp-servers/).

### OpenChamber

Open Settings → MCP, add a local server, and use the executable and arguments from Verbemo's instructions. Select the intended personal or project scope. The OpenChamber backend must run on the same computer as Verbemo; a remote backend is outside this setup. See [OpenChamber's MCP instructions](https://github.com/openchamber/openchamber/blob/main/packages/docs/content/docs/mcp.mdx).

## Available tools

| Tool | Result |
| --- | --- |
| `list_meetings` | Compact cards, filters, and continuation cursor |
| `search_meetings` | Literal case-insensitive matches in current transcripts or summaries |
| `get_meeting` | Saved metadata, participants, speaker bindings, and processing state |
| `list_transcript_versions` | Current and archived saved transcript generations |
| `get_meeting_transcript` | Original ordered segments, optional time interval, and continuation cursor |
| `get_meeting_summary` | Markdown pages with stale/provenance information |
| `get_meeting_audio` | Finalized saved audio and, through the bridge, downloaded local files |
| `get_settings` | Known effective/saved settings with secrets and hooks redacted |

These operations do not transcribe, summarize, rename, migrate, recover, mix, or modify a meeting. Unknown participants stay unknown. A saved stale summary remains available and is marked stale. When an older summary's source version cannot be proven, `source_version_id` is null.

Participant filters match saved participant names or email addresses, not participant IDs. Time filters use the actual saved recording start and require an explicit UTC offset. The end boundary is exclusive. Transcript time ranges return intersecting segments intact. Reuse the returned cursor with the same arguments; if relevant content changes, restart from the first page after `content_changed`.

Lists default to 20 items and allow up to 100. Transcript pages default to 100 segments and allow up to 500. Text pages target 64 KiB without cutting an individual segment. A result that cannot fit the 1 MiB serialized response limit fails with `response_too_large` instead of silently truncating text.

## Audio copies

The HTTP service streams only finalized permitted audio, with authenticated GET/HEAD and a single byte Range. It does not embed the complete recording as base64 in a tool response. The bridge downloads the file into the client's artifact directory, validates the transfer, and returns `local_path` with its metadata. Partial failed downloads are removed.

Completed copies belong to the client. Disabling MCP, rotating its token, changing the library, or quitting Verbemo revokes new and active transfers from Verbemo; it cannot erase a copy the client has already received. Remove finished copies according to the client's retention needs.

## Access and troubleshooting

MCP is off by default and binds only to `127.0.0.1`. Explicit local enabling or token rotation creates the credential in the platform's protected local store. Syncing an enabled configuration to another computer does not generate a token there.

Access displays the token only as `***`. Its Copy button, keyboard Copy and context-menu Copy insert the full current token; selecting part of the mask still copies the whole token. Rotating the token changes the next copied value and revokes existing access. Standard bridge instructions contain no token.

The bridge keeps the token out of model-visible arguments and results. Direct HTTP integrations must supply `Authorization: Bearer …`; never put the token in a URL. The service requires its exact Host header and rejects a supplied Origin unless it is the service's own origin. Missing Origin is allowed for native clients. There is no permissive CORS or public/LAN listener.

If configuration or credential storage cannot be read safely, access remains closed. Repair the configuration through the application; MCP does not replace an unreadable file with defaults. Check the application's actual server status before reconnecting.

The current Windows file boundary supports drive-root paths and rejects UNC and device roots. A network-share library is not supported by this implementation.

Connecting an AI client gives that client read access to the selected library. The client may send retrieved content to its model provider. Verbemo's MCP service itself does not invoke a model provider.
