# Verbemo: самостоятельное приложение и релизы

Дата: 2026-10-19. Статус: спецификация для проверки пользователем; реализация ещё не начата.

## Цель

Переименовать приложение в Verbemo на macOS и Windows и подготовить собственный
путь сборки, подписи, публикации и обновления через `ekho/verbemo`. Сохранить
существующие функции, включая текущую macOS-реализацию локальной диаризации.
Установленное приложение Amanu, его данные и репозитории не изменять.

Результат этой работы — проверенный код и инструменты подготовки релизов.
Публикация первого публичного релиза и установка приложения вместо Amanu в задачу
не входят. Наличие инструментов не означает наличие сертификатов или принятую
проверку Windows на реальном компьютере.

## Идентичность приложения

| Объект | Новое значение |
| --- | --- |
| Название приложения, .app, .exe | `Verbemo` |
| Команда и Swift package / executable target | `verbemo` |
| macOS bundle ID, префикс собственных IPC/notification/service identifiers | `name.ekho.verbemo` |
| .NET namespaces / проекты | `Verbemo.*` |
| Windows Velopack package ID | `Verbemo` |
| Репозиторий, поддержка и исходники | `https://github.com/ekho/verbemo` |
| Начальная собственная версия в корневом VERSION | `0.1.0` |

Переименовать активные исходники, package/project references, строки интерфейса
на обоих языках, справку CLI, ярлыки, автозапуск, имена исполняемых файлов и
метаданные пакетов. Переименовать ресурсы с именем продукта и ссылки на них;
новый рисунок значка не требуется. Существующие имена сторонних библиотек,
моделей и их лицензии не менять.

Собственные переменные окружения `AMANU_*` переименовать в `VERBEMO_*` вместе
со всеми вызывающими скриптами, CI и тестами. Стандартные переменные провайдеров
и сторонних инструментов сохранить.

Исторические release notes, отчёты и исходные copyright notices сохраняются.
Упоминание происхождения от Amanu допустимо в документации и атрибуции;
обращение работающего Verbemo к инфраструктуре Amanu — нет.

## Данные и совместная установка

- Verbemo — отдельная установка, без автоматической замены Amanu.
- macOS: собственные `~/.config/verbemo`, каталоги кеша/моделей Verbemo,
  настройки, ключи, login item и идентификаторы одиночного экземпляра.
- Windows: собственные каталоги приложения/настроек/моделей, ярлыки,
  автозапуск и имена mutex/IPC с именем Verbemo.
- Каталог записей по умолчанию на обеих платформах — `~/Verbemo Recordings`
  (на Windows — под текущим профилем пользователя).
- Существующие записи можно открыть через уже имеющийся выбор каталога.
  Данные и кеши Amanu автоматически не переносить, не удалять и не переименовывать.
- Уже имеющиеся интеграции с выбранными пользователем CLI, провайдерами моделей
  и ключами этих провайдеров сохранить; это не инфраструктура Amanu.
- Новое приложение получает собственные разрешения ОС. Повторный запрос
  разрешений не маскировать под сбой старой установки.

## Единая исходная база Windows и macOS

Перенести Windows-код из указанной Windows-ветки в рабочую ветку Verbemo,
сохранив исходную историю и ссылку на исходный commit. Не сливать всю ветку
целиком: её история существенно разошлась с текущим `master`, и это может
перезаписать macOS-изменения. Область переноса — Windows-проекты, их runtime/build
скрипты, тесты и необходимые части Windows workflow.

После интеграции обе платформы собираются из одного подготовленного commit и
корневого `VERSION`. Обновить `AGENTS.md`: специальный старый маршрут Windows
через Amanu release-ветку перестаёт быть маршрутом релиза Verbemo.

## Собственные релизы и обновления

Пока собственный домен не выбран, достаточно GitHub Releases. Собственный сервер,
SSH-хост автора, `samatme3`, `amanu.me`, `stats.amanu.me`, Azure/Fands-настройки
автора и их ключи не требуются и не используются.

| Объект | Значение |
| --- | --- |
| macOS release tag | `verbemo-v<VERSION>` |
| Windows release tag | `verbemo-windows-v<VERSION>` |
| macOS installer | `Verbemo-<VERSION>-macos-universal.dmg` |
| Windows installer | `Verbemo-<VERSION>-Setup.exe` |
| Постоянный tag для собственных update feeds | `verbemo-updates` |
| Sparkle feed | `https://github.com/ekho/verbemo/releases/download/verbemo-updates/appcast.xml` |
| Windows SimpleWebSource | `https://github.com/ekho/verbemo/releases/download/verbemo-updates` |
| Windows channel | `stable` |

Новые префиксы тегов отделяют релизы Verbemo от сохранённых тегов Amanu.
Существующие теги и опубликованные артефакты не переписывать.

macOS сохраняет Sparkle, но использует собственную Ed25519-пару. Публичный ключ
встраивается в релизную сборку; закрытый передаётся через явно заданный файл
за пределами Git. Старый публичный ключ удаляется из активной конфигурации.
Локальная сборка без ключа запускается без работающего автообновления;
релизная сборка без собственного ключа завершается ошибкой до публикации.

Windows сохраняет Velopack и использует `SimpleWebSource` с явным собственным
адресом. Пакеты `.nupkg` должны находиться рядом с `releases.stable.json`:
сначала загрузить и проверить пакеты, потом обновлять метаданные канала.
Версионные пакеты в `verbemo-updates` добавляются без перезаписи существующих
файлов. Изменяемыми остаются только заранее определённые файлы метаданных.

Порядок публикации для обеих платформ: проверки → сборка и подпись → проверка
подписи/пакета → загрузка версионных артефактов → проверка скачивания и хешей →
обновление соответствующего feed. Публикации сериализуются, чтобы параллельные
workflow не затёрли метаданные. Проверка запрещает откат версии/build number.
Ошибки обновления не прерывают запись; установка ждёт завершения записи и
обработки, как в существующей реализации.

## Настройки подписи и публикации

- Убрать из скриптов авторские аккаунты, абсолютные пути, автоматическое
  чтение чужого `.env.asc`, SSH-деплой и публикацию в `gsamat/amanu`.
- Все GitHub-записи имеют явную цель `ekho/verbemo`; preflight отклоняет другой
  origin/репозиторий и версию пакета, не совпадающую с `VERSION`.
- Документировать переменные `VERBEMO_SPARKLE_PRIVATE_KEY_FILE`,
  `VERBEMO_SPARKLE_PUBLIC_KEY`, `VERBEMO_SIGN_ID`, `VERBEMO_NOTARY_KEY_FILE`,
  `VERBEMO_NOTARY_KEY_ID`, `VERBEMO_NOTARY_ISSUER_ID`.
- Для Windows предусмотреть собственный сертификат через явно заданные
  параметры локального скрипта / секреты `VERBEMO_WINDOWS_CERTIFICATE_BASE64`
  и `VERBEMO_WINDOWS_CERTIFICATE_PASSWORD`. Не использовать чужой publisher.
- Отсутствующие ключи и сертификаты дают понятную ошибку preflight. Не
  подменять подписанный релиз ad-hoc/unsigned сборкой. Локальные development
  сборки без релизных credentials должны оставаться возможными.
- Подготовить пример конфигурации без секретов и gitignore для локального
  файла. Сами сертификаты, ключи и секреты не добавлять в Git и логи.
- Workflow публикации — ручные с явным ref/version; обычный push и PR только
  собирают и проверяют. Подготовка к релизу не запускает публичную публикацию.
- Обновить checksums, проверки имени installer, README download updater и
  package manifests для нового продукта. Исторические каталожные манифесты
  Amanu хранить только как историю, не публиковать как Verbemo.

## Статистика, сайт и документация

Отправку продуктовой и веб-статистики отключить. Не подменять старый endpoint
на выдуманный домен и не создавать новый analytics backend в этой задаче.
Убрать вводящие в заблуждение включённые переключатели/заявления об отправке
статистики; обновить privacy notice и описание сетевых обращений.

Обновить README, страницу About, контакты поддержки, активную документацию,
landing pages и их проверки для Verbemo. До появления собственных артефактов
ссылки ведут на страницу Releases, а не на несуществующий installer или сборку
Amanu. Убрать активные конфиги деплоя на домены и серверы автора. Собственный
сайт в этой задаче не публиковать; релиз не должен зависеть от деплоя сайта.

## Проверки и критерии готовности

1. Тесты идентичности/путей доказывают раздельные bundle/package IDs, настройки,
   кеши, IPC и каталог записей. Данные Amanu остаются нетронутыми.
2. Проверка активных runtime/build/release файлов отклоняет старые сервисные
   адреса, signing key и publisher. Атрибуция и исторические документы отделены
   явной областью проверки; сторонние зависимости не переименовываются.
3. macOS: Swift tests, universal build, проверка bundle/подписи/ресурсов,
   CLI help/doctor и запуск реального `Verbemo.app` с собственным состоянием.
4. Windows: restore/build/core + Windows live tests, проверка имени installer,
   installation/update/uninstall и фактический GUI flow на Windows-хосте.
   GitHub Actions на Windows может подтвердить сборку и автоматические тесты,
   но не заменяет проверку пользовательского потока на подключённом компьютере.
5. Тесты preflight проверяют неверный origin/version, отсутствие ключей,
   запрет перезаписи версионных файлов, порядок публикации и сухой прогон без
   загрузки. Test transports не отправляют сетевые запросы и секреты.
6. Feed-тесты проверяют собственные URL, package ID, подписи/хеши и наличие
   всех referenced пакетов. Метаданные не публикуются раньше артефактов.
7. Выполненные проверки, неподтверждённые проверки Windows и отсутствие
   credentials перечисляются отдельно. Без них не заявлять, что подписанный
   публичный релиз или runtime acceptance уже состоялись.

## Границы

Без нового дизайна интерфейса, изменений алгоритмов распознавания/диаризации,
автоматического переноса данных, собственного analytics backend и публикации
релиза или сайта. `ekho/amanu`, `gsamat/amanu` и их инфраструктура не меняются.
