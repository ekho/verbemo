# Локальный MCP-сервер Verbemo

Дата: 2026-10-28. Статус: согласовано в issue #63; реализация в работе.

## Цель и согласованные решения

Дать AI-клиентам доступ к существующим встречам Verbemo: найти нужную встречу,
прочитать сведения, расшифровку или сводку, получить сохранённое аудио и узнать
применяемые настройки. Все восемь инструментов работают только на чтение.

Пользователь согласовал:

- встроенный сервер, доступный только пока запущен Verbemo;
- фильтры по времени, участникам, названию, наличию расшифровки/сводки,
  полноте привязки голосов; дополнительно — аудио и состоянию обработки;
- текстовый поиск по расшифровкам и сводкам, доступ к версиям расшифровки;
- отдельный инструмент получения аудио: агент самостоятельно получает файл
  для анализа или передачи дальше; ручное скачивание пользователем не подходит;
- первый этап для локальных клиентов ChatGPT/Codex, Claude/Claude Code,
  OpenCode/OpenChamber на компьютере с Verbemo;
- постраничную выдачу, чтение фрагментов, разделение приглашённых и говоривших,
  скрытие секретов настроек, аутентификацию и проверку Origin.

Одинаковый внешний контракт на macOS и Windows входит в согласованный этап.
Детали ниже, включая значения лимитов и поведение пограничных случаев, приняты
вместе с документом; технические решения исполнителя зафиксированы в плане.

## Рассмотренные подходы

| Подход | Что даёт | Цена и ограничения | Решение |
| --- | --- | --- | --- |
| Сервер внутри приложения | Использует его библиотеку, настройки и текущее состояние; управляется из настроек | Требует запущенного приложения | Выбран пользователем |
| Самостоятельная фоновая служба | Доступ при закрытом приложении | Отдельный жизненный цикл, установка и согласование состояния | Отклонён для этого этапа |

Закрытие окна не выключает сервер. Подтверждённый выход из приложения,
выключение MCP в настройках и смена профиля закрывают доступ и текущие передачи.
Самостоятельный демон, автоматический запуск приложения по запросу MCP,
облачный мост и публичный адрес в этот этап не входят.

## Основа в существующем коде

Проверенная исходная ревизия: `4161d87853eb69b587a778bb39c87a219d2f84c1`.

> 🧠 **From Hindsight memory (Component map)** — macOS и Windows имеют отдельные
> нативные реализации в одном репозитории; macOS объединяет CLI и приложение,
> Windows выделяет модели в Verbemo.Core. Это сверено с Package.swift и
> windows/src; общим будет контракт MCP, а не новая общая библиотека данных.

- `Sessions/SessionInventory.swift`, `SessionState.swift` и Windows
  `Core/Processing/SessionInventory.cs` читают каталоги встреч и состояние этапов.
- `Sessions/TranscriptVersions.swift` и Windows `TranscriptVersions.cs` отвечают
  за текущую и архивные версии. На macOS идентичность версии учитывает JSON
  расшифровки и связанную с ним генерацию временной разметки голосов.
- `SpeakerNames.swift`, `MeetingCalendarMetadata.swift` и их Windows-эквиваленты
  разделяют голос, подпись голоса и связь с участником.
- `MeetingPlaybackView.sources`, `MeetingPresentation.audioFiles` и Windows
  `MeetingPlayer.Tracks` описывают сохранённые файлы и смещения дорожек.
- `SettingsSchema`, `Config`, Windows `AppSettings`/`SettingsDocument` — источники
  схемы и применяемых значений. Не создавать вторую таблицу значений по умолчанию.
- `AppDelegate`/владелец приложения и `VerbemoRuntime` владеют запуском,
  настройками и остановкой сервисов; сервер не принадлежит окну.

У существующих helpers есть чтение с `nil`/пустым результатом при ошибке.
На границе MCP отсутствие файла надо отличать от повреждения или отказа доступа.
Готовый UI helper не считается достаточной проверкой безопасности пути.

## Подключение и управление

Основной транспорт — MCP Streamable HTTP по `http://127.0.0.1:<port>/mcp`.
Слушать только loopback; `0.0.0.0`, доступ из LAN и произвольный bind address
не предоставлять. Фиксированный настраиваемый непривилегированный порт выбирается
при планировании; при конфликте показать ошибку, не подменять адрес молча.
IPv4-адрес в инструкции подключения устраняет зависимость от разрешения localhost.

Сервер выключен по умолчанию. Настройки предоставляют включение, порт,
фактический адрес, состояние/ошибку, копирование токена и его замену.
Изменения применяются без перезапуска приложения. Включение после перезапуска
следует сохранённой настройке, если локальный токен доступен и конфиг читается.
Синхронизация config.json на другой компьютер не должна создавать токен или
включать неаутентифицированный доступ автоматически.

Из блока MCP в настройках обеих платформ открывается встроенная инструкция
подключения. Для ChatGPT/Codex, Claude Desktop, Claude Code, OpenCode и OpenChamber
есть отдельные шаги и копируемая поддерживаемая команда либо конфигурационный
фрагмент. HTTP-адрес и использующие его примеры формируются из выбранного валидного
порта и обновляются вместе с копируемым текстом при его смене. Выбранный адрес
отличается от фактически работающего: выключение, ошибка запуска и ещё не применённое
изменение не должны выглядеть как успешное подключение. Инструкция stdio-адаптера
использует реальные поддерживаемые аргументы и объясняет чтение настроек приложения.
Токен в примеры не подставляется. Статус проверки совместимости указывается честно;
пользователь разрешил оставить Claude Code непроверенным из-за отсутствия входа.

Встроенный сервер обслуживает несколько клиентов. Версию протокола согласовывает
MCP initialize. Базовая цель совместимости — `2025-11-25`; фактические версии SDK
и клиентов фиксируются в плане и отчёте. Не обещать поддержку всех будущих версий.
Все инструменты объявляют readOnlyHint=true, destructiveHint=false,
idempotentHint=true, openWorldHint=false; это описание, а не механизм защиты.

Для локального клиента, требующего stdio, допустим минимальный транспортный
адаптер к этому же серверу. Он не читает библиотеку самостоятельно, не запускает
Verbemo и не продолжает обслуживать данные после его выхода. Добавлять такой
адаптер только при подтверждённой необходимости, прежде всего для Claude Desktop;
его упаковку и способ хранения клиентского токена проверить до фиксации плана.

## Общие правила данных

- Использовать opaque `meeting_id`, `version_id`, `audio_id`; клиент не передаёт
  путь к файлу. Существующие встречи доступны без миграции и записи новых sidecar.
- `meeting_id` стабилен при перезапуске и редактировании названия в метаданных.
  Привязка к настроенному корню и относительному каталогу допустима: внешнее
  перемещение/переименование папки или смена корня делает старый ID недействительным.
  Нельзя автоматически перенаправить его на другую встречу.
- `version_id` обозначает конкретную сохранённую генерацию, сохраняется при её
  архивировании. `current` — только входной селектор; ответ возвращает конкретный ID.
  Изменение имён говорящих меняет ревизию чтения, но не выдаёт себя за новый ASR-запуск.
- Даты возвращаются в ISO 8601 с offset; входные границы обязаны содержать offset.
  Фильтруется фактическое начало записи: `started_from <= started_at < started_before`.
  Плановое время календаря — отдельные поля. Неизвестное начало не проходит фильтр времени.
- Наличие материала, его актуальность и состояние обработки — разные поля.
  `has_transcript`/`has_summary` относятся к текущему сохранённому результату;
  архивные материалы доступны через версии. Сохранённая устаревшая сводка даёт
  `has_summary=true`, `summary_stale=true`, а не выдуманный успешный этап обработки.
- Nullable-фильтр наличия: true — есть, false — нет, отсутствие поля — не фильтровать.
  Повреждённый или недоступный материал не считать отсутствующим: состояние `unknown`
  не проходит ни true, ни false, а ответ содержит предупреждение об ошибке чтения.
- Списки возвращают `items`, `next_cursor`; лимит по умолчанию 20, максимум 100.
  Сортировка встреч по началу, затем ID; по умолчанию новые первыми, неизвестные даты
  последними. Курсор связан с фильтрами, порядком и прочитанным состоянием.
- Расшифровки, сводки и поиск стремятся к 64 КиБ полезного текста на страницу;
  длинная выдача имеет continuation cursor. Неделимый сегмент расшифровки длиннее
  этого размера возвращается единственным элементом страницы без изменения текста.
  Для всех инструментов жёсткий предел сериализованного ответа — 1 МиБ: если даже
  один сегмент, поле метаданных или настройки не помещается, вернуть
  `response_too_large`, не усекать значение. У get_settings можно запросить меньше
  ключей; у get_meeting нет обещания выгрузки неограниченной повестки.
  Курсор не содержит секретов; при изменении относящихся к нему данных — `content_changed`.
- Ошибки инструментов возвращаются через `isError=true` с машинным `code`,
  безопасным сообщением и `retryable`. Коды: `meeting_not_found`,
  `version_not_found`, `artifact_not_found`, `artifact_not_ready`,
  `data_unreadable`, `content_changed`, `invalid_cursor`, `response_too_large`,
  `server_stopping`.
  Неверные параметры и неизвестный инструмент обрабатываются по правилам MCP/JSON-RPC.
- В списках/поиске ошибка отдельной встречи даёт предупреждение и `partial=true`;
  недоступный корень даёт ошибку всего вызова. Нельзя выдавать неполную выдачу за полную.

## Инструменты

### list_meetings

Параметры: `started_from`, `started_before`, `title_contains`, `participants`,
`participant_scope` (`listed`/`speaking`), `participant_match` (`any`/`all`),
`has_transcript`, `has_summary`, `has_audio`, `participant_assignment`,
`processing_stage`, `processing_state`, `sort`, `limit`, `cursor`.

`participants` — список текстовых запросов: имена ищутся как подстроки без учёта
регистра, email — полным совпадением после принятой в приложении нормализации.
Пустые запросы отклоняются. Scope по умолчанию listed, match — any.
Несколько совпавших людей возвращаются как разные участники; одинаковое имя не
создаёт общей личности между встречами. `speaking` учитывает только голоса,
связанные с участниками в текущей версии, без догадок по тексту реплик.

`processing_stage` выбирает transcription/diarization/speaker_naming/summary;
`processing_state` выбирает pending/running/deferred/failed/off/done/cancelled/unknown.
Фильтры этапа и состояния передаются вместе. `running` и `cancelled` берутся из
достоверного состояния приложения; исчезновение задания не доказывает завершение.

Возвращать компактные карточки: ID, название, начало, длительность, источник,
участники, признаки наличия, актуальность сводки, полнота привязок и состояния этапов.
Тексты расшифровки, сводки и повестки в список не включать. Активная запись может
быть показана с `recording_state=recording|paused`; завершённый материал не выдумывается.

### get_meeting

Параметр: `meeting_id`. Возвращать карточку и подробные метаданные: сохранённый
календарный контекст, запланированное время, состав участников, таблицу голосов и
привязок текущей версии, счётчики неизвестных/непривязанных голосов, текущий
version_id, число сохранённых версий, доступность аудио и безопасные ошибки этапов.
Не включать тексты расшифровки и сводки, логи и доказательные цитаты из speakers.json.
Повестка допускается как сохранённый контекст встречи; произвольный сырой meta.json
не выдаётся. Ссылка на конференцию с встроенным кодом доступа не выдаётся в v1.

### list_transcript_versions

Параметры: `meeting_id`, `limit`, `cursor`. Версия содержит ID, дату создания,
engine/model, `is_current`, сведения о разделении голосов, наличие и актуальность
сводки, полноту привязок. Незавершённый запрос обработки не становится сохранённой
версией: его состояние находится в get_meeting. Порядок — новые версии первыми,
с ID как дополнительным ключом сортировки.

### get_meeting_transcript

Параметры: `meeting_id`, `version_id` (по умолчанию current), `start_ms`, `end_ms`,
`limit` (число сегментов, по умолчанию 100, максимум 500), `cursor`.
Отрицательные/нечисловые границы и неположительный диапазон отклоняются.

Ответ: конкретная версия, `revision`, язык если известен, engine/model,
сегменты `{segment_index, start_ms, end_ms, speaker_id, speaker_name, participant_id, text}`,
`next_cursor`. Сохранять порядок, текст, таймкоды и исходные speaker_id.
Неизвестная личность остаётся null; отображаемое имя не считается доказательством связи.
Диапазон выбирает пересекающиеся сегменты целиком, без выдуманного обрезания слов.
После первого запроса cursor привязан к версии и revision, включая подписи голосов.

### get_meeting_summary

Параметры: `meeting_id`, `version_id` (current по умолчанию), `cursor`.
Ответ: Markdown, `revision`, запрошенный version_id, `source_version_id`,
`stale`, `next_cursor`. Если происхождение старой сводки нельзя доказать,
source_version_id=null. Нельзя приписывать её новой версии по расположению файла.
Чтение не запускает создание или обновление сводки.

### search_meetings

Параметры: непустой `query`, `scope` (transcript/summary/both, по умолчанию both),
фильтры list_meetings, `limit`, `cursor`. В первой версии поиск только по текущим
сохранённым материалам; архивную версию можно читать явно через её ID.

Поиск — буквальная подстрока без учёта регистра, без regex, embeddings и LLM.
Результат содержит meeting_id, конкретный version_id, вид материала, фрагмент
до 400 символов и segment_index/таймкод для расшифровки. Совпадения сводки
содержат stale и source_version_id, если известен. Результаты упорядочиваются
по времени встречи, затем ID, виду материала и позиции совпадения.
Сканирование отменяемое, выполняется вне UI-потока; продолжение не пропускает
оставшуюся часть библиотеки из-за внутреннего ограничения работы за один запрос.

### get_meeting_audio

Параметр: `meeting_id`. Аудио относится к записи, а не к версии расшифровки.
Ответ: список доступных ресурсов с audio_id, ролью дорожки, именем файла,
MIME type, размером, длительностью если измерена, `start_offset_ms` и download URI.
Если есть завершённый общий архив аудио, отдавать его как предпочтительный ресурс;
иначе — существующие дорожки с их смещениями. Не выполнять смешивание,
перекодирование, обрезку по времени или восстановление удалённого аудио.

На стороне сервера инструмент возвращает MCP resource_link и те же метаданные
в structuredContent. Это описание материала, а не завершённое получение файла.
Файл скачивается отдельным HTTP GET с Authorization на том же loopback-сервере;
поддерживаются HEAD и один байтовый Range для частичного скачивания/продолжения.
Ссылка не содержит токен; GET/HEAD требуют тот же доступ, что и /mcp.
Данные передаются потоком, а не целиком как base64 внутри ответа инструмента.

Обязательный результат для каждого заявленного клиента: его агент может без
ручного скачивания получить полный файл и использовать его как вход следующей
операции. Ссылка в ответе, инструкция пользователю или файл, доступный лишь
внешнему браузеру, этот результат не обеспечивают.

Получение выполняет локальное окружение клиента либо его адаптер: добавляет
Authorization из защищённой конфигурации, скачивает поток в принадлежащий клиенту
каталог временных материалов и предоставляет агенту доступный ему файловый
артефакт/путь. Нельзя считать любой путь на компьютере доступным агенту: проверяется
доступ из фактического окружения следующей операции. Если клиент принимает файл
через иной нативный механизм, использовать его с теми же критериями приёмки.
Токен не передаётся модели, в аргументы инструмента или в текст ответа. Копия
файла принадлежит клиенту; это получение результата чтения, а не изменение библиотеки.
Её срок хранения и удаление следуют правилам временных материалов клиента.

Способ интеграции для каждой установленной версии клиента — обязательная первая
проверка в плане реализации после согласования этой спецификации. Использовать
существующие возможности клиента прежде, чем писать адаптер. Если механизм
не позволяет агенту получить файл, совместимость этого клиента не считается
достигнутой: нужен работающий адаптер либо отдельное решение пользователя об
изменении охвата. Не заменять требование выдачей ссылки или ручным скачиванием.
Встроенное воспроизведение в чате и способность выбранной модели понимать аудио
не являются обязательствами сервера; доступ агента к полному файлу — является.

Активно записываемый или заменяемый файл даёт artifact_not_ready; выдача начинается
только после завершения записи/финализации конкретного файла. Открытый файл привязан
к ревизии; смена доступного материала не подменяет байты в незавершённом скачивании.
Удалённое аудио даёт artifact_not_found; отсутствие прав — data_unreadable.
После выключения сервера, смены корня или токена старый доступ прекращается.
Это отзывает новые и текущие передачи из Verbemo, но не стирает копию,
которую клиент уже успел получить.

### get_settings

Параметр `keys` необязателен: без него все известные доступные настройки, с ним —
выбранные пути. Использовать стандартные snake_case-пути приложения.
Возвращать platform, configuration_status и записи с key, value, source
(configured/default/runtime), needs_restart и признаком ожидающего применения.
Для параметров, читаемых при старте, отдельно показывать применённое и сохранённое
значение. При нечитаемой конфигурации MCP закрыт, включая get_settings:
диагностика и последнее прочитанное состояние остаются в приложении. Через MCP
не подменять текущую конфигурацию пустой/дефолтной и не обещать last_known.

Для секрета возвращать только configured/redacted, без value; это касается и
токена MCP. Сырые JSON/переменные окружения, содержимое файлов ключей и credential
store не экспортировать. Экспорт строится по проверенному списку полей схемы.
Произвольные hook-команды/аргументы скрывать целиком, URL с userinfo/query/fragment
санитизировать, неизвестные поля не включать. Поля-ссылки на файл ключа не дают
возможности прочитать этот файл. Политика безопасного экспорта входит в общие fixtures.

## Полнота привязки участников

Значения: complete / incomplete / unknown. Фильтр может выбрать любое из них;
отсутствующий фильтр включает все. Считать привязку по выбранной версии,
для списка встреч — по текущей.

- complete: есть непустая расшифровка, все различимые голоса в её репликах связаны
  с существующими участниками встречи и нет реплик с неопределённым говорящим;
- incomplete: есть проверяемые голоса/реплики, но хотя бы одна связь отсутствует,
  ссылается на отсутствующего участника или есть неизвестный говорящий;
- unknown: нет расшифровки, она пустая/нечитаемая либо разметка представляет
  смешанный канал нескольких людей и не позволяет проверить полноту.

Нельзя получить complete из 0/0, подписанного вручную имени без participant_id
или названия общего канала. Приглашённые, которые молчали, не препятствуют complete.
Счётчики `linked_speakers`, `unlinked_speakers`, `unknown_segments` объясняют результат;
если их нельзя вычислить, они null, а не нули. Это полнота сохранённых связей,
не гарантия правильности распознавания голоса или реальной личности.

## Безопасность и согласованное чтение

Случайный токен минимум 256 бит, только Authorization: Bearer, сравнение без
зависимости времени от совпавшего префикса. Хранить отдельно от config.json:
собственный закрытый файл ключа на macOS по паттерну Credentials.writeSecret,
SecretStore на Windows. Никогда не помещать его в логи, URL или get_settings.
Замена токена отзывает старый и активные передачи; ошибка доступа к хранилищу
оставляет сервер закрытым. При нечитаемой конфигурации сервер прекращает приём
запросов до восстановления, сохраняя настройку включения без записи поверх ошибки.

Host проверяется на точный ожидаемый loopback-host/порт. При наличии Origin
принимается только собственный origin; остальные, включая null, отклоняются.
Отсутствующий Origin допустим для нативных клиентов. Не открывать общий CORS.
Для защищённых путей нет исключений из аутентификации; несовпадение Origin — 403,
отсутствующий/неверный токен — 401 без раскрытия наличия встречи.

Все ID разрешаются сервером внутри выбранной библиотеки. Отклонять traversal,
неразрешённые расширения/роли файлов, симлинки и Windows reparse points на пути
от доверенного корня до файла; защищаться от подмены между проверкой и открытием.
Не делать универсальный файловый сервер. Ограничить размер входного запроса,
параллелизм, время чтения и размер текстового ответа. Не следовать ссылкам из данных.

Чтение нескольких файлов использует существующие блокировки и проверку ревизии;
нельзя смешать transcript одной генерации с speakers/summary другой. Незавершённый
commit journal не является готовым результатом. При гонке — ограниченный повтор,
затем content_changed/artifact_not_ready, без запуска recovery из MCP-запроса.
Длительное скачивание не держит блокировку встречи. Pending deletion, скрытый
staging импорта и перемещённые в корзину встречи не выдаются.

Выход закрывает приём запросов сразу после принятого решения выйти, отменяет
чтения и скачивания, освобождает сокеты/файлы с ограниченным ожиданием. Клиент не
может удерживать завершение приложения бесконечным скачиванием. Отмена диалога
выхода не должна оставить MCP выключенным. MCP не меняет существующие гарантии
сохранения записи и остановки фоновой обработки.

Тексты встреч считаются данными, а не инструкциями серверу. Сервер не отправляет
их провайдерам сам, но подключённый AI-клиент может отправить полученное своей
модели. Включение MCP должно кратко объяснять этот доступ к библиотеке.

## Совместимость и приёмка клиентов

Документация проверена 2026-10-28; это сведения о возможностях транспорта,
а не выполненная проверка Verbemo. Перед реализацией зафиксировать установленные
версии клиентов. Если нужная версия отсутствует, явно указать непроверенную строку.

| Клиент | Предполагаемый маршрут | Что проверить на практике |
| --- | --- | --- |
| ChatGPT Desktop / Codex в локальном окружении | Streamable HTTP + Bearer | Обнаружение восьми tools, фильтры, продолжение текста, самостоятельное получение аудио агентом |
| Claude Code | HTTP + Authorization | Те же сценарии, ошибки при выключенном Verbemo |
| Claude Desktop | Его локальная MCP-интеграция; адаптер к HTTP при необходимости | Поддерживаемый способ настройки, tools и фактическое получение аудио |
| OpenCode | Remote MCP URL на loopback, headers | Фактическая версия конфигурации V1/V2, токен, все материалы |
| OpenChamber | MCP URL/headers на локальном backend | Где выполняется backend, доступ к loopback, tools и аудио |

Для каждого клиента отдельно отметить: соединение, чтение текста, самостоятельное
получение файла агентом, встроенное воспроизведение. Первые три обязательны для
заявления о совместимости; проигрывание в чате необязательно. Проверка аудио
проходит из реального клиентского окружения, включая последующую операцию с файлом.
Нельзя заменить её curl-запросом разработчика вне клиента, видимой resource_link
или ручным переносом файла пользователем. Адаптер, если нужен, входит в работу
по совместимости и не становится самостоятельным сервером библиотеки.

Обычные облачные подключения ChatGPT/Claude и удалённый backend OpenChamber
не получают доступ к этому localhost автоматически. Туннели и облачные подключения
отложены по прямому решению пользователя; никакие реальные клиентские настройки
или токены на стадии проектирования не меняются.

## Изменяемые области и проверки реализации

План должен охватить сервер/транспорт, доступ к материалам, безопасный экспорт
настроек, управление токеном, запуск/остановку в runtime, настройки на обеих
платформах, документацию подключения и общие контрактные fixtures.
Переиспользовать существующие модели и helpers; не строить новую БД, очередь
обработки или постоянный индекс. Список версий/метаданные можно временно кешировать
с ограничением размера и инвалидированием; это не источник истины.

Необходимые проверки:

1. Общие JSON fixtures для восьми инструментов на Swift и C#: фильтры,
   часовые пояса/границы дат, одинаковые имена, unknown/0 голосов, старые встречи,
   устаревшая сводка, отсутствующие/повреждённые материалы, курсоры и лимиты.
2. Неизменность файлов библиотеки после всех MCP-вызовов, включая ошибки;
   отсутствие генерации/повторной обработки и сетевых вызовов к AI-провайдерам.
3. Токен/Origin/Host, смена токена, конфликты порта, traversal/симлинки/reparse,
   отсутствие секретов в настройках, ошибках и логах, ограничение запросов.
4. Смена версии/имён во время чтения, удаление, финализация аудио, HTTP Range,
   отмена и остановка приложения; отсутствие смешивания материалов и зависаний.
5. Реальные локальные клиенты по таблице, с искусственной библиотекой без
   пользовательских встреч и секретов. Проверить небольшой файл и длинную запись,
   превышающую лимит текстового ответа MCP. Агент получает файл без ручной помощи
   и выполняет следующую локальную операцию с ним; размер и хеш результата
   совпадают с исходным аудио. Отдельно проверить несколько дорожек, отмену,
   недоступный файл и повторное получение после перезапуска приложения.
6. На macOS — сборка, относящиеся к изменению тесты и реальный GUI-проход
   включения/выключения/закрытия окна/выхода. На Windows — сборка, тесты и GUI
   на подключённом Windows-хосте после проверки его доступности. CI на macOS
   и отчёт агента не заменяют эту Windows-проверку.

До планирования уточнить реализацию transport/SDK, порт, точное кодирование ID,
ограничения одновременных запросов и комплект поставки адаптера Claude Desktop.
Эти технические решения оставлены исполнителю, если сохраняют контракт и область
доступа. Изменение набора возможностей, вынос сервера из приложения или добавление
облачного доступа требуют отдельного решения пользователя.
